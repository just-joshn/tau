# File restoration after compaction

The independent text-file restoration path runs after a valid manual, automatic or reactive summary. It rereads selected files, adds their current contents to model context and rebuilds process-local Read state. Complete restored text can authorize Edit/Write; a reference cannot. Clear and resume still start with empty process-local state.

## Independent implementation

ReadState now tracks filesystem mtimes for complete and partial views, keeping digest baselines only for complete model-visible text. It retains tau's512-entry bound and normalized SHA256 checks. Candidates sort by mtime; tau resolves equal timestamps by most recent local touch. Successful Write/Edit records the resulting mtime when available.

file-restoration.ts selects candidates, rereads through the existing workspace and policy checks, restores full supported text or emits an independently worded reference, and prepares a new cache. tools.ts excludes the root instruction file that tau actually loads and accepts explicit restorationExcludedPaths for embedding-supplied instruction/plan services. Retained Read calls suppress restoration; local readContentOmitted metadata represents omitted-content notices. Tau does not currently emit the original unchanged-read notices or classify their proprietary prose. Canonical candidate paths and workspace-normalized retained paths are the supported comparison; original path/device semantics are broader.

The numbered restored text is an ordinary user message, with separate restoredFile metadata for local persistence. Metadata and omitted-read flags stay off the API wire. The aggregate estimate uses tau's independent attachment representation, not the original proprietary schema. Accepted full text establishes a new baseline; references have candidate metadata without an edit baseline. Entries not restored lose their old baselines, including retained-read exclusions. Original guard exceptions are not guessed.

compaction.ts stages restoration only after a usable summary and appends it after retained messages. Cancellation before commit leaves both history and prior cache unchanged. This deliberate atomicity differs from the original clear-before-await internal ordering; original aborted-cache behavior is not claimed. The same shared ReadState object is rebuilt so an active automatic-compaction executor immediately sees its new baselines. Manual CLI no longer replaces that object after a successful restoration.

The direct provider independently implements the verified beta count route, one auxiliary retry, bounded64KiB JSON, configured full-response timeout, cancellation and estimate fallback. It never follows redirects or discloses error bodies. Auxiliary counts do not spend --max-api-attempts, which remains the generation allowance. Count retry waits retain tau's60-second ceiling; source SDK hints can be longer. The port does not recreate count memoization, additional eligible betas, account/provider capability gates, credentials renewal, cloud adapters or gateway501 sample-completion fallback. A later focused pass established the model identity: preferred larger-model summaries keep the main Read context for counting. agent.ts now passes restorationModel separately from the summary request model. Direct compactContext embeddings can supply that main-model identity explicitly; manual defaults use the request model.

Restored files remain bounded regular UTF-8/BOM UTF-16LE text; general explicit-range Read now scans larger regular files as described in [Read](read-contract.md). Original larger reads/media/PDF/notebooks, managed/user/local/auto-memory instruction discovery, plan service, at-mentions, landing/device rules, original attachment transforms, memory/skills/hooks and other post-compaction attachments remain open. Byte-over-limit references now use the recovered262144-byte default; the earlier64KiB bound was superseded by the Read-budget pass. Full original parity remains unfinished.
