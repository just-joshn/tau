## Working workflows at this baseline

These workflows are functional in tau against deterministic loopback model fixtures or fake providers. Original comparisons are recorded separately by exact scenario.

1. **Local coding:** prompt → search/Read → complete model-visible file baseline → Edit/Write → further model round → answer → own session saved. Real UTF-8/UTF-16LE/BOM/newline files, permissions and stale content are exercised. The newest compiled CLI test streams Write input above1MiB, edits its tail and overwrites the large file.
2. **Large-file coding:** ordinary refusal/page → `allow_large` → counted full Read → mutation; same-reply large reads share claims and can page when room is exhausted. New write-size PTY verifies300KB Read→Edit, external tail change rejection, reread recovery, Edit→Write, mode preservation, clear/reset and clean exit.
3. **Controlled tools:** availability/deny/allow plus current permission mode → tool advertisement/dispatch → approved work or explicit error; print mode cannot interactively grant approval. Shell cancellation/nonzero status and search pagination are covered.
4. **Context continuation:** long or server-refused context → selected summary planning/fallback/repair → retained groups and restored files → main-model continuation → own save/resume. Manual compaction, clear and resume work interactively.
5. **Transport recovery:** fragmented stream or selected HTTP/body failure → source-backed bounded decision/counters → partial retention or provisional rollback → retry/JSON/configured model fallback → consistent history. Original runtime and live account behavior remain unverified.

6. **Ordinary MCP stdio:** explicit config → in-place discovery/real initialization → model advertisement → approved call → structured/image result → dynamic tools refresh → continuation → save/resume; default/explicit denial prevents server calls, and every fixture child exits. Tests cover legacy/modern envelopes, errors, cancellation, idle/hard deadlines, resource/audio/PDF projection and collisions. Six ordinary MCP differential cases are verified; the table’s broader policies remain open.

## Integration seams and ownership

- `ToolExecutor.definitions`/`execute` are the existing model-facing extension seam; `prepareCompaction` and `setReadContext` carry context lifecycle. External tools must pass the same availability/deny/permission path rather than bypass it.
- `toolNameSchema` remains the six built-ins; external catalogs are composed by `tool-router.ts`, with independent MCP availability and ordinary MCP rule matching. `beforeModelRequest` awaits catalog refresh. Rich `apiContent` survives sessions and replaces textual terminal summaries only in API projection; raw MCP metadata stays local. Broader source identity/managed/deferred policy still needs integration.
- `Provider.complete` returns completed responses; text/reset/usage callbacks do not yet expose a general streaming tool-dispatch contract. Original streaming execution needs explicit cancellation/retry ownership before integration, not simply earlier side effects.
- `loadLaunchConfiguration` now owns launch settings/source-aware policy. `buildBaseSystemPrompt` and `InstructionContext` separate saved system prompts from eager/nested instruction delivery. Legacy `buildSystemPrompt` remains a scaffold API, not the actual CLI instruction path.
- `SessionStore` deliberately owns tau's format today. Original compatibility requires a migration/projection layer and differential fixtures; do not silently reinterpret old tau JSON as original transcripts.

Existing contracts retain detailed evidence, while historical test counts/“never execute” statements remain historical.
