# Integrated local skills and command hooks

This is a partial reconstruction of installed Claude Code2.1.326. Recovered application JavaScript is the primary source; actual Ghidra batches match the selected nonexecutable embedded bytes. Those matches establish provenance, not runtime equivalence.

The CLI consumes ordinary settings command hooks for PreToolUse, PostToolUse, PostToolUseFailure, SessionStart and Stop. Tool inputs pass preflight before PreToolUse; rewritten inputs pass full validation and permission arbitration again. Explicit denies/asks, protected writes and interaction requirements survive hook permission grants. Original assistant tool inputs remain in history; effective input and raw response metadata stay local.

Hook additional context is stored as ordered local metadata. Projection restores Pre→result→Post/failure rows, sanitizes reminder wrappers, relocates them and applies the source string/rich append rules. Post-only context can fold into a tool result; pre+post can remain sibling user text. Event names alone do not decide placement. Failure hooks retain the failure and add feedback. Their continuation fields do not act as Stop. Stop can request another model round using the same prompt-wide API and turn allowances. SessionStart runs at startup/resume/clear and supports bounded asynchronous cleanup. Full event coverage, original transcript compatibility, settings watches, arbitrary attachment kinds, protected classifications and reminder-fold replay gates remain incomplete.

Local skills load metadata from managed, user and nearest-to-ancestor project roots. Catalog descriptions are offered before bodies; a successful invocation adds the expanded body to model context. `/skills` lists user-invocable entries; `/NAME args` invokes an admitted local skill. Model calls use the Skill tool. Source gates and explicit Skill permission rules arbitrate invocation separately from frontmatter tool grants.

Grants and command denies affect the current query. Model context layers remain local metadata: the primary API model is captured once at query entry, after slash expansion. A model-invoked Skill does not reroute later API rounds; a slash skill can select the model before that snapshot. Effort is read live on later rounds, with environment/settings precedence and known first-party capabilities/defaults. A new ordinary user query, clear or resume resets them; saved session settings are unchanged. A supported explicit deny always wins over a skill grant. `--ignore-persisted-trust` withholds project automatic grants in noninteractive mode; managed-only and personal-configuration restrictions have separate source gates. Existing file validation, Read-before-edit requirements and sensitive-path holds continue to apply.

Supported automatic grants currently cover exact tool names and ordinary MCP name rules. Unsupported command/path grants are diagnosed and withheld; unsupported denies refuse invocation. Skill hooks register per session with source quotas, deduplication, stable IDs and success-only once removal. The settings registry retains its own state as skill hooks change. Disabled, managed-only, unsupported or rejected registrations also withhold dependent automatic grants. Effort serializes named levels into output_config with its beta header; numeric values do not automatically become named effort. Unknown/custom capability policies, account/server caps and migration state remain explicit limits. Forked skills and shell substitutions fail explicitly until their execution paths are implemented. Plugin/synced/legacy catalogs, progressive nested discovery and complete model/effort policy remain required.

History projection coalesces assistants only when an explicit response ID matches across tool-result carriers. Adjacent user messages merge with the source's text seam and result-first ordering. It preserves signed reasoning, call IDs and original inputs. The original hook fixture reused a response ID, so its grouping is not evidence that ordinary distinct-response tool rounds should collapse.

Compiled workflows verify Skill→Write with temporary grants, frozen inline query model and grant reset on fresh-process resume; slash model selection; inherited deny; ignored-persisted-trust withholding; session hook once success/failure; and live effort/env/cap/numeric/unset behavior. The ten-case original hook comparison covers selected files/events/error flags, with wire, default and context differences retained. Full product equivalence is unfinished.

Eight selected original/Tau Skill cases and a corrected resume comparison cover49 mock requests. Two skill-hook cases plus a corrected Post comparison cover22 requests/seven hook children. Three effort cases cover12 requests. The corrected Post channel and actual tool-result ownership, high→low effort and medium environment/cap precedence match the measured original. All isolation and cleanup checks pass. Thinking display, complete headers/schemas/cache text/reminders/result framing remain different.
