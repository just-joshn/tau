## Routing in tau

`createWebTools(...).wrap(base)` in `cli.ts` handles both names with the hook,
permission and policy pipeline used by other built-ins. With no `--tools`
selection the tools are callable but not advertised, which stands in for the
original's deferral until a ToolSearch host registers `webToolDefinitions()`.
`--tools WebFetch,WebSearch` advertises them. `tool-policy.ts` accepts
`WebFetch`, `WebSearch` and `WebFetch(<content>)` in CLI and settings rules.

## Known differences

- HTML conversion is an HTMLRewriter rule set modeled on turndown defaults, not turndown. Tables, nested list spacing and escaping edge cases can differ.
- Binary bodies are decoded as text; the original saves them to a file (`$He`/`wfe`).
- The original's CCR proxy, artifact links, provenance prompts, dedup notes, failed-earlier notes, citations (`CLAUDE_CODE_WEBSEARCH_CITATIONS`), the web search session budget and search-service routes are not ported.
- Results above 50000 characters are not persisted to a file.
- The side queries send a plain string system prompt; the original prefixes its billing header and identity blocks.
- The User-Agent is `Claude-User (tau; +https://support.anthropic.com/)`.
- Lean prompt variants (`ZI`) are not selected; tau always sends the full descriptions.
- Child agents do not get the web tools yet.
