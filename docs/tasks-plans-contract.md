# Local tasks and main-session plans

This describes the bounded TypeScript implementation at the841-test checkpoint. Recovered JavaScript establishes selected application behavior; Ghidra matches imported nonexecutable Bun bytes. Original comparisons use owned fixtures under freshly verified disposable isolation. None establishes full CLI compatibility.

TaskCreate/Get/Update/List use a session-scoped list or explicit environment list ID, atomic JSON files, a high-water ID and cooperative locks. Enablement follows the recovered model/tool gates; loading the default Opus5.5 does not itself enable the older task catalog. TaskCreate starts pending. TaskCreated blocking feedback deletes the new record; TaskCompleted blocking feedback prevents every update in that operation. Missing records and completion holds are domain results without an `is_error` flag. Metadata null deletes keys; reverse status changes, self edges and cycles are accepted. Reciprocal edges update existing targets; missing edge targets are ignored. Get and List deliberately expose different projections. Team, storageV5, notifications and background scheduling are outside this local implementation.

The CLI host preserves explicit deny/ask rules, tool availability and command hooks around task operations. Query policy overlays remain separate from persistent task files. Clear/resume recreate the host and use the correct session/list identity. TaskCompleted output includes the configured command and arguments. Three original/Tau workflows match selected intermediate results and exact final JSON bytes across38 mock API requests. See `artifacts/differential-pass/tasks-tau-before`.

EnterPlanMode changes the main session's mode and remembers its previous mode. ExitPlanMode snapshots the designated plan file, requests approval and restores the prior mode only after approval. A denial preserves planning. Model-provided plan/path fields are removed at the ingestion boundary; trusted approval or validated hook replacements use a separate path. The ordinary main session may enter automatically; exit remains an interaction unless a source-admitted hook exception and host policy both allow it. Team/fork and worktree behavior are explicit unsupported seams.

The host selects the admitted plans directory and creates its own deterministic session slug. It does not copy the original private slug word lists. Read/Write/Edit admit only the designated session file or owned agent-file family under the pinned canonical plan root, with symlink/hardlink checks. An admitted plan file can be outside cwd. This exception does not erase explicit deny/ask rules, preflight validation, read/stale guards or sensitive-file checks. Own JSON session state persists active planning, slug and previous mode; this is not original transcript compatibility.

Headless Plan entry/exit requires an explicit approval channel. The MCP bridge uses a connected hidden tool and sends `{tool_name,input,tool_use_id}`. It parses the first text content block as bounded strict allow/deny JSON, preserves optional validated input replacements and handles interruption. Omitted/empty replacement means snapshot the current plan again. The approval tool remains callable by the authority bridge while hidden from the model. Its filtered MCP facade forwards refreshes. Valid updatedPermissions are diagnosed but not applied; generic file/Bash approval rewrites and non-stdio providers are not yet integrated.
